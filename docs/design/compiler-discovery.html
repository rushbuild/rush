Build normally

Leave RUSH_CPP_DISCOVERY unset to use Auto:

unset RUSH_CPP_DISCOVERY
rush build //app:app

Start with supported literal analysis and normal reuse. When analysis reports conditional includes (ConditionalIncludes) or token pasting (TokenPasting, ##) that needs compiler execution, let Auto start one fresh analysis attempt and run the whole selected invocation locally with reuse disabled.

Expect header guards with nested includes to select this path in many header-heavy builds. The selected invocation includes your requested targets and the actions needed to build them. Rush reports the switch before those build actions run.

Follow one path for this build

Run the build again normally. Auto starts its analysis again. If either supported reason recurs, expect the whole selected invocation to execute afresh, including unchanged repeats.

Supported literal builds and pure Mojo builds keep their existing execution and reuse behavior.

Choose an explicit build policy when needed

Leave the variable unset for normal Auto builds, or set one of these exact policies.
RUSH_CPP_DISCOVERYBuild behavior
Unset the variableStart with literal analysis; switch once for a supported conditional-include or token-pasting reason.
literalRequire supported literal analysis and report unsupported constructs as errors.
always-run-local-v1Choose whole-invocation, always-run local execution directly.
uncached-diagnostic-v1Use the same always-run execution mechanism with the existing diagnostic label.

For strict literal analysis on one build:

RUSH_CPP_DISCOVERY=literal rush build //app:app

Use local Linux execution and supported native rules for the always-run modes. Leave --use-scheduler off and unset RUSH_USE_SCHEDULER.

Use rush build for the automatic transition. The nested builds in rush test keep strict literal analysis; the always-run modes are build-only.

Keep one coherent invocation

Fresh analysis

Rush finishes the first attempt and discards its temporary analysis state. The fresh attempt checks the same request with current inputs and producers.

Execution ownership

The switch releases the first attempt’s shared workspace lease, then takes exclusive ownership and retires earlier reusable plans before native actions begin.

Cancellation and errors

The request’s cancellation state carries into the retry. Started work keeps its execution ownership through cleanup. Execution failures return as build errors.

Inspect the analysis boundary

This boundary is before native actions or cached-output restoration. Analysis can prepare its owned include paths. The fresh attempt stages and validates its paths again.

Treat compiler dependency records as observations. Require a separately validated input closure before admitting cached reuse.
